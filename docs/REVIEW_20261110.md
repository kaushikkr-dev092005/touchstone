## Semantic checks and evaluation

`invoice_roles.py` binds exact source values to known header and line-item roles.
It accepts the existing six header and three item grammars. It preserves source
offsets and values; Unicode normalization is confined to label matching. A known
wrong role is rejected even if every financial equation balances. Unsupported or
ambiguous roles require review, including repeated identical header values.

Invoice and PO identifiers have independent syntax checks. PO identity, supplier,
currency, remaining authorization and payment-reference conflicts remain mandatory
exception checks. A task ID is not treated as the expected invoice ID. Complete
ITEM coverage and integer-cent arithmetic remain separate checks.

The verdict exposes structural validity, semantic role binding and arithmetic
validity separately. Only `passed AND decision=candidate` counts as a candidate.
Review is never accepted. No extraction verdict authorizes an invoice payment.

The shared deterministic parser now covers all supported source grammars. On the
old corpus it produces 180 strictly correct drafts, including drafts that require
review; 72 are candidates. The prior narrow 24/180 baseline overstated the need for
an LLM. This stronger baseline must be used for comparisons.

## Prospective corpus

[Frozen manifest](../bench/results/m3-v2/dataset/manifest.json): 120 calibration
sources and 60 new sources across equals-record, value-parenthesis, arrow-record
and wrapped-value layouts. Sources and offline labels have separate hashes. The
corpus was frozen before new model output and is write-once. Profiling sends only
public sources; scoring reads labels afterwards.

This is implementer-authored synthetic data, not independently blind vendor/OCR
data. Unfamiliar layouts may yield useful strictly correct review drafts without
meeting the deterministic role grammar for automatic candidate status. Reports
distinguish those drafts from candidates and quantify value beyond the stronger tool.
The 95% Wilson lower-bound calibration target and complete 95% holdout check with
zero observed false accepts remain unchanged.

A separate [comparison corpus](../bench/results/m4-v2/dataset/manifest.json) uses a
different seed. Its matched workload takes one familiar control and 15 new-layout

## Integrated and comparison boundaries

The banked CLI can reuse a hosted authorization from the same journal and scope.
`--prefunded-only` blocks instead of depositing. `--retain-unused-float` closes the
customer side, reads back retained token float and performs no withdrawal. An invoice
demonstration refuses to authorize or buy without an eligible measured profile bound
to the frozen corpus; delivered model identity must match. Existing legacy recovery
terms are preserved. Fiat capture and token spend are separate entries, never a bridge.

The comparison runner binds each public source, code version, qualification and fault
schedule before dispatch. It reports candidates/review/rejected, strictly correct
outputs and correct review drafts. Every charged failure counts in provider cost per
strictly correct answer. API credits are reported separately at published rates;
unknown usage retains conservative credit exposure. Unresolved payments suppress
final unit-cost figures. No policy win or measured saving is claimed without a run.
Qualification overhead, CPU, energy and human-review costs require separate accounting.

## Comparison with AgentXPayU / Margin

source-reviewed, not independently executed. Its README provides stronger integrated
financial/demo evidence, including sandbox authorization changes and reconciled runs.

measurement and a reproducible signed fault. The user's criticism of judge readiness
and semantic verification was justified. The README now starts with a no-key path and
an evidence table. No unsupported claim of overall superiority is made.
