## Review and verification

The initial horizon was too thin relative to the recording. Its surface depth and
particle count were increased, retaining the same buffered renderer. The field
now uses 5,200 particles on desktop and 2,300 on narrow screens before any watchdog
adjustment. The hero's wider aspect and text scrim mean the source's full portrait
field is not copied pixel for pixel. Its radial motion, flattening horizon and
measured cadence are reproduced procedurally. The prior planet limb is removed.

Chromium captures cover both formations, 1440×900 and 390×844, light/dark ledger,
pause/replay and reduced motion. The recorded local preview measured about 60fps
and about 1.4ms of particle rendering per frame at full desktop density. This is a
headless Windows Chromium observation, not a guarantee on other hardware or while
llama.cpp is under load. No external browser requests or page errors were observed.

The functional browser workflow passed both billing policies, session/Host/Origin
checks, SSE updates, kill/resume, closure and reconciliation. A new assertion checks
that confirmed halt stops the particle field. **247 Python tests and 49 Node tests
pass**, including two new motion/scheduling regressions. All financial validation
uses isolated simulated data, with zero external transactions.
